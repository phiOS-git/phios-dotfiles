# phiOS — the generation contract (master plan §6.7).
#
# One row per themed target. Four fields separated by `|`, whitespace around
# each field is trimmed, `#` starts a comment, blank lines are ignored.
#
#   template  | destination | reload | class
#
#   template     path from the repository root
#   destination  path relative to $HOME, matching the installer's convention
#   reload       command that makes a running instance pick the file up, or
#                `-` when the class has no reload path at all
#   class        A hot reload  |  B runtime reconfiguration  |  C restart
#
# `phios-render` takes an explicit template path and `phios-install` walks
# `profiles/*/templates/` directly, so neither needs the destination column.
# `phi theme set` (S-12) is what consumes this file — render, set, preview,
# list and check all resolve tokens through it — and it owns the reload
# mechanics: a `[unknown]` row is rendered and reported as not yet wired,
# never guessed at or silently skipped. Every row below points at a template
# that exists as of S-03.
#
# `[unknown]` in the reload column is deliberate and is not a placeholder to
# be guessed at. A wrong reload command fails silently — the file is written,
# the application keeps its old colours, and nothing reports it. Each one is
# filled in by the step that implements that target's reload.
#
# The perimeter of §6.7 is wider than this file: phi-shell, the GTK/Qt themes,
# Librewolf's userChrome.css, the XCursor theme and the Plymouth theme are all
# themed targets. They get their row from the step that creates their
# template. A row here without a template is a row that cannot be rendered.
